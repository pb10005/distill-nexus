# 適合性検証ループ

「テストが通った」は完了ではありません。完了とは、**全ACが証拠付きで pass か、blocked として人間に返っている**状態です。

## 前提

`specs/**/requirements.yaml` が単一の正。実装・テスト・議論はすべてこれに従属します。存在しない場合、このループは実行できません。先に要件を確定させてください。

## ループ

```
 trace-matrix ──▶ verifier ──▶ scope-auditor ──▶ reconcile ──▶ gate
   機械検査       独立判定       逆方向監査       要件へ還元    合否
       ▲                                            │
       └──────────── 修正は最大2周まで ◀────────────┘
```

### 1. 機械検査

```bash
npx tsx scripts/trace-matrix.ts --base origin/main --json
```

LLMの判断を入れる前に、機械で分かる穴（未カバーAC、宙に浮いた参照、未記録の仮定、frozen なのに未決事項が残っている等）を潰します。ここで出る error はLLMに判定させる価値がありません。

**この `--json` の出力は手元に残しておき、そのまま verifier / scope-auditor の起動プロンプトに貼り付けてください。** 両者ともコードを編集しないため、この時点の結果はそれぞれの起動直前まで有効です。同じ計算をサブエージェントに再実行させるのは、判定の独立性には寄与しない重複コストです（実装の意図や言い訳ではなく機械的な計算結果を渡すことは、検証の独立性を損ないません）。

### 2. 独立検証

`verifier` サブエージェントを起動します。**あなた（実装したセッション）が自分で判定してはいけません。** 自分の成果物を採点する主体は必ず甘くなります。

verifier には requirements.yaml と成果物への参照、および手順1で取得した `trace-matrix --json` の出力だけを渡します。実装の経緯・設計意図・「ここは意図的にこうした」という説明を渡さないでください。それを渡した時点で、検証ではなく承認になります。

### 3. 逆方向監査

`scope-auditor` サブエージェントを起動し、要件に無い実装を洗い出します。手順1で取得した `trace-matrix --json` の出力（`UNTRACED_CHANGE` 一覧）を渡してください。順方向だけ見ていると、頼まれていない機能が恒久的な保守債務として残ります。

### 4. 差分の還元（reconcile）

fail / blocked / 分類C を、**実装のバグ**と**要件の欠落**に仕分けます。この工程が無いと要件ファイルが実装から乖離し、以降のループが全部無意味になります。

- 実装のバグ → 修正して 1. に戻る
- 要件の欠落・誤り → requirements.yaml を更新（AC追加、`then` の修正、`out_of_scope` への追記）し、変更理由を1行残す
- 判断が要る → `open_questions` に積み、人間へ

### 5. ゲート

```bash
npm run gate
```

## 停止条件（重要）

同一ACが2回 fail すると `record-verdict.ts` が自動的に `blocked` へ降格させ、`open_questions` に起票します。**この打ち切りを回避して修正を続けないでください。** 2回直せないものは、ほぼ確実に実装ではなく要件の問題です。人間に返すのが正しい振る舞いです。

同様に、以下は自力で解決せず人間に上げます:
- `out_of_scope` に触れる変更が必要になった
- ACどうしが矛盾している
- ACを満たすには `assumptions` の仮決めを確定させる必要がある

## 禁止事項

- テストをACに合わせて弱めること（アサーション削除、skip、期待値の書き換え）。ACが間違っているなら直すのは**要件**であって、テストの緩和ではありません
- 証拠なしに `status: pass` を書くこと
- requirements.yaml を手で編集して検証結果を記録すること（必ず `record-verdict.ts` 経由）

## スクリプト

| コマンド | 用途 |
|---|---|
| `npx tsx scripts/trace-matrix.ts [--json] [--strict] [--base <ref>]` | 順方向・逆方向・仮定のトレース |
| `npx tsx scripts/record-verdict.ts --ac AC-001 --verdict pass\|fail\|blocked --evidence <file:line> --note "..."` | 書き戻し。pass は evidence 必須、fail/blocked は note 必須。2回 fail で自動 blocked |
| `npm run gate` | トレース + テスト + 型のゲート |
